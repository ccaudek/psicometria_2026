Obiettivi di questo segmento

In questo segmento affronteremo:

  1. Prior predictive distribution — cosa “sa” il modello prima dei dati;
  2. Posterior predictive distribution — cosa “prevede” il modello dopo i dati;
  3. Algoritmo di Metropolis — come il computer esplora la posterior;
  4. Errori di tipo M e di tipo S — perché il paradigma frequentista può ingannare.

Formato della prova

Ogni domanda avrà 5 alternative, una sola corretta.

Le risposte possono essere:

  • verbali (interpretazione, spiegazione concettuale);
  • numeriche (risultato di un calcolo o di una simulazione con set.seed() fissato e \(N\) simulazioni alto).

Esercizio 1 — Prior predictive distribution

Scenario: Uno psicologo vuole stimare la proporzione \(\theta\) di pazienti che migliorano dopo una terapia breve. Prima di raccogliere dati, sceglie una distribuzione a priori.

Consideriamo due possibili prior:

  • Prior A: \(\theta \sim \text{Beta}(1, 1)\)
  • Prior B: \(\theta \sim \text{Beta}(0.5, 0.5)\)

Per ciascuna prior, si genera la distribuzione predittiva a priori: si estraggono valori di \(\theta\) dalla prior, poi per ciascun \(\theta\) si simula il numero di successi su \(n = 20\) pazienti.

(8 minuti; circa 2 minuti per ciascuna domanda)

Domanda 1.1 — [Numerica]

Usate set.seed(42) e \(N = 100\,000\) simulazioni dalla prior predictive con Prior A (\(\text{Beta}(1,1)\)). Qual è la deviazione standard del numero di successi? (Arrotondate a una cifra decimale.)

Soluzione 1.1

set.seed(42)
n_sim <- 100000
n_paz <- 20

theta_A <- rbeta(n_sim, 1, 1)
y_A <- rbinom(n_sim, size = n_paz, prob = theta_A)

cat("SD (Prior A):", round(sd(y_A), 1), "\n")
SD (Prior A): 6.1

Risposta: 6.1

Domanda 1.2 — [Numerica]

Con lo stesso set.seed(42) e \(N = 100\,000\), calcolate la deviazione standard dalla prior predictive con Prior B (\(\text{Beta}(0.5, 0.5)\)). (Una cifra decimale.)

Soluzione 1.2

set.seed(42)
theta_B <- rbeta(n_sim, 0.5, 0.5)
y_B <- rbinom(n_sim, size = n_paz, prob = theta_B)

cat("SD (Prior B):", round(sd(y_B), 1), "\n")
SD (Prior B): 7.3

Risposta: 7.3

Domanda 1.3 — [Scelta multipla]

Quale affermazione descrive correttamente il significato del prior predictive check?

  1. Serve a verificare che la prior sia centrata sul valore vero del parametro.
  2. Serve a stimare la potenza statistica dello studio.
  3. Serve a verificare che la combinazione prior + modello produca previsioni a priori plausibili, prima di osservare i dati.
  4. Serve a confrontare la posterior con la prior.
  5. Serve a calcolare il valore-\(p\) del modello.

Soluzione 1.3

Risposta corretta: (c)

Il prior predictive check risponde alla domanda: “Se il mondo funzionasse come il mio modello + prior, che dati vedrei?” Se le previsioni sono implausibili (es. tutti 0 o tutti 20 successi), la prior va rivista — e lo si fa prima di toccare i dati reali.

Esercizio 2 — Posterior predictive distribution

Scenario: Lo psicologo raccoglie i dati: su \(n = 20\) pazienti, \(y = 14\) migliorano. Usa Prior A: \(\theta \sim \text{Beta}(1, 1)\).

La posterior è: \(\text{Beta}(1 + 14, 1 + 6) = \text{Beta}(15, 7)\).

(8 minuti; circa 2 minuti per ciascuna domanda)

Domanda 2.1 — [Numerica]

Qual è la media della distribuzione a posteriori \(\text{Beta}(15, 7)\)? (Tre cifre decimali.)

Soluzione 2.1

alpha_post <- 15
beta_post  <- 7
media_post <- alpha_post / (alpha_post + beta_post)
cat("Media a posteriori:", round(media_post, 3), "\n")
Media a posteriori: 0.682

Risposta: 0.682

Domanda 2.2 — [Numerica]

Usate set.seed(42) e \(N = 100\,000\) simulazioni dalla posterior predictive (nuovo gruppo di 20 pazienti). Qual è \(P(\tilde{Y} \geq 15 \mid \text{dati})\)? (Due cifre decimali.)

Soluzione 2.2

set.seed(42)
theta_post <- rbeta(n_sim, alpha_post, beta_post)
y_pred <- rbinom(n_sim, size = 20, prob = theta_post)

P_ge_15 <- mean(y_pred >= 15)
cat("P(Y_nuovo >= 15 | dati) =", round(P_ge_15, 2), "\n")
P(Y_nuovo >= 15 | dati) = 0.41

Risposta: 0.41

Domanda 2.3 — [Scelta multipla]

La posterior predictive distribution è più dispersa di una previsione generata usando solo la stima puntuale \(\hat{\theta} = 14/20 = 0.70\). Perché?

  1. Perché il modello Beta-Binomiale sovrastima sempre la varianza.
  2. Perché la prior è troppo vaga.
  3. Perché la posterior predictive include sia l’incertezza campionaria sia l’incertezza sul parametro \(\theta\).
  4. Perché la posterior è una distribuzione discreta.
  5. Non è più dispersa: le due distribuzioni hanno la stessa varianza.

Soluzione 2.3

Risposta corretta: (c)

La previsione puntuale con \(\hat{\theta} = 0.70\) genera dati simulati da \(\text{Bin}(20, 0.70)\) — include solo la variabilità campionaria. La posterior predictive genera prima \(\theta\) dalla posterior (incertezza sul parametro) e poi \(\tilde{Y}\) da \(\text{Bin}(20, \theta)\) — due fonti di variabilità.

set.seed(42)
y_puntuale <- rbinom(n_sim, size = 20, prob = 0.70)
cat("SD puntuale:", round(sd(y_puntuale), 2), "\n")
SD puntuale: 2.06

SD posterior predictive: 2.81

Esercizio 3 — Algoritmo di Metropolis

Contesto: L’algoritmo di Metropolis è il cuore dei metodi MCMC usati da Stan e brms.

Ecco un’implementazione per campionare dalla \(\text{Beta}(3, 7)\) senza usare rbeta():

metropolis <- function(n_iter, theta_start, sd_proposta, seed = 42) {
  set.seed(seed)
  campioni <- numeric(n_iter)
  campioni[1] <- theta_start
  accettati <- 0
  for (i in 2:n_iter) {
    theta_proposto <- rnorm(1, mean = campioni[i-1], sd = sd_proposta)
    if (theta_proposto < 0 | theta_proposto > 1) {
      campioni[i] <- campioni[i-1]
      next
    }
    r <- dbeta(theta_proposto, 3, 7) / dbeta(campioni[i-1], 3, 7)
    if (runif(1) < r) {
      campioni[i] <- theta_proposto
      accettati <- accettati + 1
    } else {
      campioni[i] <- campioni[i-1]
    }
  }
  list(campioni = campioni, tasso = accettati / n_iter)
}

(8 minuti; 2 minuti per ciascuna domanda)

Domanda 3.1 — [Numerica]

Eseguite metropolis(100000, 0.5, 0.1, seed = 42), scartate i primi 5 000 campioni (burn-in) e calcolate la media dei rimanenti. (Due cifre decimali.)

Promemoria: la media teorica della \(\text{Beta}(3, 7)\) è \(3/(3+7) = 0.30\).

Soluzione 3.1

ris <- metropolis(100000, 0.5, 0.1, seed = 42)
camp <- ris$campioni[5001:100000]
cat("Media campioni:", round(mean(camp), 2), "\n")
Media campioni: 0.3

Risposta: 0.3

Domanda 3.2 — [Numerica]

Qual è il tasso di accettazione (proporzione di proposte accettate)? (Due cifre decimali.)

Soluzione 3.2

cat("Tasso di accettazione:", round(ris$tasso, 2), "\n")
Tasso di accettazione: 0.78

Risposta: 0.78

Domanda 3.3 — [Scelta multipla]

Se si usa sd_proposta = 0.01 anziché 0.1, cosa succede?

  1. Il tasso di accettazione scende e la catena esplora meglio la distribuzione.
  2. Il tasso di accettazione sale ma la catena esplora lentamente, con alta autocorrelazione.
  3. Non cambia nulla: il risultato è identico.
  4. La catena diverge e non converge alla distribuzione target.
  5. L’algoritmo si blocca perché le proposte sono troppo piccole.

Soluzione 3.3

Risposta corretta: (b)

ris_piccola <- metropolis(100000, 0.5, 0.01, seed = 42)
cat("Tasso (SD=0.01):", round(ris_piccola$tasso, 2), "\n")
Tasso (SD=0.01): 0.98 
cat("Tasso (SD=0.10):", round(ris$tasso, 2), "\n")
Tasso (SD=0.10): 0.78

Proposte piccole → quasi tutte accettate, ma la catena si muove a passi microscopici → esplorazione inefficiente, alta autocorrelazione.

Domanda 3.4 — [Scelta multipla]

Perché l’algoritmo di Metropolis funziona senza conoscere la costante di normalizzazione \(Z\) della distribuzione target?

  1. Perché usa solo le derivate della densità.
  2. Perché discretizza lo spazio dei parametri con una griglia.
  3. Perché al passo di accettazione si calcola un rapporto di densità, e la costante si cancella.
  4. Perché la distribuzione di proposta è già normalizzata.
  5. Perché la costante è sempre uguale a 1 per le distribuzioni continue.

Soluzione 3.4

Risposta corretta: (c)

\[ r = \frac{p(\theta^*)}{p(\theta_{t-1})} = \frac{f(\theta^*)/Z}{f(\theta_{t-1})/Z} = \frac{f(\theta^*)}{f(\theta_{t-1})} \]

La costante \(Z\) si cancella. Basta valutare la densità a meno di una costante: in ambito bayesiano, questo è semplicemente \(\text{prior} \times \text{verosimiglianza}\).

Esercizio 4 — Errori di tipo M e di tipo S

Contesto: Un ricercatore vuole studiare un effetto piccolo \((d = 0.20)\) con \(n = 25\) per gruppo.

set.seed(42)
n_studi <- 100000
n_per_gruppo <- 25
d_vero <- 0.20
SE <- sqrt(2 / n_per_gruppo)

d_hat <- rnorm(n_studi, mean = d_vero, sd = SE)
z_stat <- d_hat / SE
significativi <- abs(z_stat) > 1.96
d_signif <- d_hat[significativi]

(8 minuti; 2 minuti a domanda)

Domanda 4.1 — [Numerica]

Qual è la potenza approssimata dello studio (proporzione di risultati significativi su 100 000 simulazioni)? (Due cifre decimali.)

Soluzione 4.1

potenza <- mean(significativi)
cat("Potenza:", round(potenza, 2), "\n")
Potenza: 0.11

Risposta: 0.11

Domanda 4.2 — [Numerica]

Tra gli studi significativi, qual è il rapporto di esagerazione (Type M), cioè \(\text{media}(|\hat{d}_\text{signif}|) \,/\, d_\text{vero}\)? (Una cifra decimale.)

Soluzione 4.2

M_ratio <- mean(abs(d_signif)) / d_vero
cat("Rapporto M:", round(M_ratio, 1), "\n")
Rapporto M: 3.4

Risposta: 3.4 — l’effetto stimato tra i significativi è circa 3.4 volte il valore vero.

Domanda 4.3 — [Numerica]

Tra gli studi significativi, quale percentuale ha il segno sbagliato (Type S error)? (Arrotondate all’intero.)

Soluzione 4.3

S_error <- mean(d_signif < 0) * 100
cat("Errore di segno:", round(S_error), "%\n")
Errore di segno: 4 %

Risposta: 4%

Domanda 4.4 — [Scelta multipla]

Quale affermazione descrive meglio le implicazioni degli errori di tipo M e S per la ricerca psicologica?

  1. Se la potenza è alta, gli errori M e S sono più gravi.
  2. La significatività statistica garantisce che la stima sia accurata indipendentemente dalla potenza.
  3. Con bassa potenza, il filtro della significatività tende a selezionare stime esagerate e talvolta di segno opposto al vero effetto.
  4. Gli errori M e S si verificano solo con l’approccio bayesiano.
  5. L’errore di tipo S è più frequente dell’errore di tipo M.

Soluzione 4.4

Risposta corretta: (c)

La significatività statistica con bassa potenza funziona come un filtro distorcente: seleziona le stime che, per caso, hanno superato la soglia critica. Queste stime sono sistematicamente esagerate (Type M) e, in una piccola percentuale di casi, hanno il segno invertito (Type S).

L’approccio bayesiano riduce il problema perché non filtra in base a una soglia, ma quantifica l’intera distribuzione dell’effetto.
